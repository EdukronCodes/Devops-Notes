### Basic Azure DevOps Interview Questions

**Q1. What is DevOps?**  
DevOps is a methodology that combines software development (Dev) and IT operations (Ops) to improve the software development lifecycle. It emphasizes communication, collaboration, integration, and automation to enable faster, more reliable delivery. It can be visualized as an infinite loop of build, test, release, and monitor.  
*Source: 2, 3, 4*

**Q2. Why use DevOps?**  
DevOps enables shorter development cycles, faster innovation, reduced deployment failures, better collaboration, and easier maintenance. Benefits include continuous delivery, improved efficiency and scalability, and better application security.  
*Source: 2, 3*

**Q3. How does DevOps work?**  
DevOps uses practices, tools, and a cultural philosophy that automate and integrate processes between development and IT. Teams often merge so engineers work across the lifecycle (development, test, deployment, operations). When security is integrated, it is called DevSecOps.  
*Source: 2*

**Q4. What is Azure DevOps?**  
Azure DevOps is a Microsoft cloud service that provides a set of tools for the entire software development lifecycle: Agile planning, source control (Git/TFVC), builds and releases, and application insights. It can be accessed via web or IDE client.  
*Source: 2, 4, 5*

**Q5. What are the benefits of DevOps?**  
Faster delivery of features, more stable environments, improved communication and collaboration, more time to innovate, better quality and reliability, security, and competitive advantage.  
*Source: 2*

**Q6. Name a few DevOps tools.**  
GitHub, Bitbucket, GitLab, Docker, Kubernetes, Mesos, Prometheus, Dynatrace, AppDynamics, Splunk, Datadog, Jenkins, TeamCity, Bamboo, GitLab CI, CircleCI, Travis CI, AWS CodeDeploy, Octopus Deploy.  
*Source: 2*

**Q7. What are Azure Boards?**  
Azure Boards is a service for managing work in software projects. It provides tracking for tasks, bugs, and features; Kanban boards; customizable dashboards; sprint planning; and integrated reporting.  
*Source: 2, 4*

**Q8. What is Azure Repos?**  
Azure Repos is a set of version control tools. It offers Git and Team Foundation Version Control (TFVC), pull requests, code search, webhooks, and API integration.  
*Source: 2, 4*

**Q9. What are Azure Pipelines?**  
Azure Pipelines is a cloud-based CI/CD service that automatically builds and tests code. It supports many languages and project types and can deploy to various targets. It provides continuous integration and continuous delivery.  
*Source: 2, 4, 8*

**Q10. What are Azure Artifacts?**  
Azure Artifacts is a service for creating, hosting, and sharing packages (e.g. NuGet, npm, Maven, Python) within the organization. It provides versioning, dependency management, package feeds, and integration with Azure DevOps.  
*Source: 2, 4*

**Q11. What containers does Azure DevOps support?**  
Docker, Azure Kubernetes Service (AKS), ASP.NET with containers, and Azure Service Fabric applications with Docker support.  
*Source: 2*

**Q12. What are Azure Test Plans?**  
Azure Test Plans provides manual and exploratory testing, continuous testing, and test case management. It integrates with Azure Boards and Azure Repos.  
*Source: 2*

**Q13. List some benefits of Azure Pipelines.**  
Flexible pricing (including free tier for open source), collaboration and reporting via Boards and Metrics, security and compliance (e.g. SOC 2, ISO 27001), extensibility with custom tasks, deployment to multiple environments (on-prem, Azure, AWS), advanced testing (unit, integration, acceptance; JUnit, NUnit, xUnit), CI/CD automation, and cross-platform support (Windows, macOS, Linux; Java, C#, Python, JavaScript).  
*Source: 2*

**Q14. What is the use of Selenium in DevOps?**  
Selenium is used for browser automation and web application testing in DevOps pipelines. It enables rapid, repeatable testing and supports multiple operating systems.  
*Source: 2*

### Intermediate Azure DevOps Interview Questions

**Q15. What is a multi-stage pipeline?**  
A multi-stage pipeline splits the CI/CD process into stages (e.g. build, test, deploy). Each stage runs in sequence; the next stage runs only if the current one succeeds. Stages can be used to deploy to dev, staging, and production.  
*Source: 2, 8*

**Q16. What are pull requests in Azure DevOps Repos?**  
A pull request (PR) is a proposal to merge changes from a branch into the main branch. It allows code review, discussion, and approval before merge. PRs are integrated with Azure Repos and support branch policies and automation.  
*Source: 2*

**Q17. Explain Forks in Azure DevOps.**  
A fork is a copy of a Git repository. It lets a developer make changes without affecting the original repo. Forks are used when you lack write access or want to experiment. In Azure DevOps, forking is integrated with Repos and supports submitting PRs back to the original repo.  
*Source: 2*

**Q18. What are Azure DevOps Projects?**  
Azure DevOps Projects provide a simplified way to create a new project with a Git repo, build pipeline, and release pipeline preconfigured with recommended settings.  
*Source: 2*

**Q19. What are fault domains and update domains?**  
In Azure, a fault domain is a group of VMs or hardware sharing a common power source and network switch. An update domain is a group of VMs updated together during planned maintenance; only one update domain is taken offline at a time.  
*Source: 2*

**Q20. What are Virtual Machine Scale Sets (VMSS)? Do they work with availability sets?**  
VMSS lets you create and manage a group of identical, load-balanced VMs that scale based on demand. Scale set instances are spread across fault domains and update domains. VMSS provides availability; they are a different construct from availability sets but both support high availability.  
*Source: 2*

**Q21. What is continuous testing? What is the use of test automation in DevOps?**  
Continuous testing is running automated tests as part of the delivery pipeline to get fast feedback on quality and risk. Test automation in DevOps helps ensure code changes do not introduce regressions and provides fast feedback for the team.  
*Source: 2*

**Q22. Differentiate between Jira and Azure DevOps.**  
Jira is focused on Agile (Scrum, Kanban) and issue tracking; Azure DevOps is a full suite (source control, CI/CD, testing, project management). Azure DevOps supports Agile, Scrum, and Waterfall; Jira is often more customizable. Azure DevOps is often used for large, enterprise projects; Jira for small to medium teams.  
*Source: 2*

**Q23. What backlog and board options are available in Azure Boards?**  
Product backlog, sprint backlog, Kanban board, dashboards, queries, reports, Git integration, test plans and results, Wiki, and extensions.  
*Source: 2*

**Q24. What is VNet (Virtual Network)?**  
VNet is an Azure service for creating and managing virtual networks in the cloud. It provides IP addressing, subnets, network security, and VPN connectivity, and is a building block for IaaS.  
*Source: 2*

### Azure Pipelines–Specific Interview Questions (YAML, CI/CD)

**Q25. How do you set up a YAML pipeline for a simple .NET Core application?**  
Define an `azure-pipelines.yml` with trigger (e.g. `main`), pool (e.g. `vmImage: 'ubuntu-latest'`), and stages. In the Build stage: UseDotNet@2, `dotnet build`, `dotnet test`. Optionally add a Deploy stage.  
*Source: 8*

**Q26. Write a YAML snippet to trigger a pipeline on changes to the ‘main’ branch only.**  
Use: `trigger: branches: include: - main`  
*Source: 8*

**Q27. How would you implement a multi-stage pipeline with separate build and deploy stages?**  
Use `stages:` with a Build stage (build, test, PublishBuildArtifacts@1) and a Deploy stage with `dependsOn: Build`, then download artifact and deploy.  
*Source: 8*

**Q28. How do you run tests using NUnit in a pipeline?**  
Use `dotnet test --configuration Release --logger trx` (and optionally other loggers). Ensure the project references NUnit and the test task runs after build.  
*Source: 8*

**Q29. Explain conditional insertion of steps in a pipeline.**  
Use the `condition` keyword on a step. Example: `condition: eq(variables['Build.SourceBranch'], 'refs/heads/main')` so the step runs only when the branch is `main`.  
*Source: 8*

**Q30. How do you deploy an application to Azure App Service from a pipeline?**  
Build the app, archive (e.g. ArchiveFiles@2), publish artifact (PublishBuildArtifacts@1), then use AzureWebApp@1 (or AzureWebApp@2) with the correct subscription and app name.  
*Source: 8*

**Q31. Describe setting up self-hosted agents.**  
Provision a machine (Windows, macOS, or Linux), download the agent from Azure DevOps, run the configuration script with org URL and PAT, register the agent in an agent pool, and run the agent service.  
*Source: 8*

**Q32. How do you use a matrix strategy for multiple configurations?**  
Use `strategy: matrix:` with key-value pairs (e.g. linux, windows, mac with different OS and Node versions). The job runs once per matrix combination.  
*Source: 8*

**Q33. How do you use environment variables in a pipeline?**  
Define `variables:` at pipeline, stage, or job level. Reference them in scripts or tasks as `$(VariableName)`.  
*Source: 8*

**Q34. How do you implement approval gates in a pipeline?**  
Use environments in Azure DevOps with approval and check requirements. In YAML, the deployment job targets an environment that has manual approval or other gates configured in the UI. (Note: Exact YAML for approvals can vary by Azure DevOps version.)  
*Source: 8*

**Q35. How do you set up and use deployment slots in Azure App Service within a pipeline?**  
Create a staging slot in the App Service. Deploy to the slot using the Azure App Service Deploy task with the slot name. Validate in staging, then swap slots with production. Rollback by swapping again if needed.  
*Source: 8*

**Q36. How do you implement caching in Azure Pipelines to speed up builds?**  
Use the Cache task (e.g. Cache@2) with a key (e.g. based on `package-lock.json` and OS) and path (e.g. `$(Pipeline.Workspace)/.npm`). Restore cache before install, then build.  
*Source: 8*

**Q37. How do you configure and run parallel jobs?**  
Define multiple jobs in the same stage. By default they run in parallel unless you use `dependsOn`. Ensure the organization has enough parallel job capacity.  
*Source: 8*

**Q38. What strategies can you use to roll back a deployment?**  
Blue-green (switch traffic back), canary (halt rollout, restore previous version), redeploy previous artifact or ARM template, automated rollback scripts, and version control (revert to a previous tag or commit).  
*Source: 8*

**Q39. How do you ensure compliance and enable auditing in pipelines?**  
Use RBAC, pipeline-as-code (YAML in repo), branch policies and permissions, compliance gates (security scans, quality checks), and Azure DevOps auditing and logging. Export logs for long-term retention.  
*Source: 8*

### Advanced and Scenario-Based Topics

**Q40. What is the Dogpile effect and how can you prevent it?**  
When a cache expires, many requests can hit the origin at once (dogpile). Prevent it with cache stampede protection or cache key locking so only one request regenerates the cache while others wait.  
*Source: 2*

**Q41. How can Jenkins be integrated with Azure Pipelines?**  
Use the Azure DevOps plugin for Jenkins to trigger builds/deployments in Azure Pipelines from Jenkins. Use Jenkins Pipeline plugin to create pipelines triggered by Azure Pipelines. Alternatively use Jenkins REST API and Azure DevOps REST API to chain the two.  
*Source: 2*

**Q42. What are some useful Jenkins plugins?**  
Job DSL, Build Time-Tracker, Amazon EC2 Plugin, SonarQube Plugin, Slack Plugin, Maven Plugin, JUnit Plugin, Git Plugin, Pipeline Plugin.  
*Source: 2*

**Q43. Can you move or copy Jenkins from one server to another?**  
Yes. Back up Jenkins data, install Jenkins on the new server, restore data, update Jenkins URL and configuration, reconfigure plugins, and test.  
*Source: 2*

**Q44. What is Infrastructure as Code (IaC)?**  
IaC is managing infrastructure through machine-readable scripts and configuration (e.g. ARM, Bicep, Terraform) instead of manual setup. It enables consistent, repeatable, and version-controlled infrastructure.  
*Source: 1, 3*

**Q45. Explain CI and CD.**  
Continuous Integration (CI): developers frequently integrate code into a shared repository with automated builds and tests. Continuous Deployment/Delivery (CD): automatically deploy or make code ready to deploy to test or production after the build stage.  
*Source: 1, 2, 3*

**Q46. What deployment strategies might be discussed in an interview?**  
Blue-green (two identical environments, switch traffic), canary (gradual rollout to a subset), rolling updates, and feature flags. Be ready to explain how you have used them.  
*Source: 1, 11, 16*

**Q47. How do you manage secrets in Azure Pipelines?**  
Use Azure Key Vault and the AzureKeyVault task, mark variables as secret in variable groups, use RBAC to limit access, and never log or expose secrets in plain text.  
*Source: 16, 17*

**Q48. What is the difference between YAML and classic pipelines?**  
YAML pipelines are defined in code, versioned in the repo, and reusable. Classic pipelines are configured in the Azure DevOps UI. YAML is the recommended approach for consistency and auditability.  
*Source: 4, 16*

**Q49. What are checkout directives in Azure Pipelines?**  
`checkout: self` checks out the default repository. `checkout: none` disables checkout (e.g. for agentless jobs or when no repo is needed).  
*Source: 16*

**Q50. What employer keywords are commonly associated with Azure DevOps roles?**  
PowerShell, Azure Kubernetes (AKS), deployment, CI/CD, Terraform, Docker, Git, Azure Pipelines, Azure Repos, Azure Boards.  
*Source: 3, 22*
