## Document Structure (per project)

Each project document includes:

1. **Azure DevOps Project Overview** – Project type, area path, iteration
2. **Project Objectives** – Goals and outcomes
3. **Azure DevOps Structure** – Repositories, Boards (Epic → Feature → User Story → Task), Pipelines, Environments
4. **End-to-End Project Flow** – ASCII flow from request/change to delivery
5. **Key Deliverables & Acceptance Criteria** – What “done” looks like
6. **Phases & Timeline** – Example phases and duration
7. **Azure DevOps Artifacts & Links** – Wiki, service connections, variable groups, permissions + **artifacts & links flow diagram**
8. **End-to-End Flow (Complete)** *(where applicable)* – Phases, RACI, decision points + **complete flow phases** and **decision points flow diagrams**

### Flow diagrams

All sections include **Mermaid flow diagrams** (flowchart style) that render in GitHub, Azure DevOps Wiki, and VS Code. Diagrams cover: objectives, repository, board hierarchy, pipeline, environment promotion, end-to-end, deliverables, phases timeline, artifacts & links; and where section 7 exists: complete flow phases and decision points.

### Detailed explanations and flows

Each major section includes:

- **Explanation** — What the section means and how it works (2–4 sentences).
- **Detailed flow (step-by-step)** — Numbered steps for how work or data moves through that section (repos, boards, pipelines, environments, end-to-end, deliverables, phases, artifacts). Where section 7 exists, a **Detailed complete flow (step-by-step)** runs from prerequisites through trigger, execute, validate, approve, release, verify, close, and feedback.

Use these docs to set up or align Azure DevOps projects, onboard teams, and track progress.
